# 登壇資料作成スキルとは？みのるん式ノウハウの公開が話題に

登壇資料作成のノウハウをClaude Skillsとして公開する動きが、エンジニアコミュニティで注目されています。きっかけは、みのるんさんが自身の資料作りの手順をスキル化して公開したことです（参考: https://qiita.com/minorun365/items/ed4c760f616cf3c0a958 ）。この記事では、登壇資料作成スキルとは何か、なぜ話題になっているのか、自分でも作れるのかを整理します。

## この記事の要点

- 登壇資料作成スキルとは、資料作りの手順やコツをClaude Skillsという形式でまとめ、Claudeに呼び出させる仕組みです。
- みのるんさんは自身の登壇資料の作り方をスキルとして公開し、他のエンジニアが同じ手順を再利用できるようにしました（出典: https://qiita.com/minorun365/items/ed4c760f616cf3c0a958 ）。
- Claude Skillsは指示やテンプレートをMarkdownでまとめたもので、個人の経験知を再利用可能な形に変換できます。

## 登壇資料作成スキルとは何か

登壇資料作成スキルとは、勉強会やカンファレンスで使うスライドの作り方を、Claude Skillsという機能でパッケージ化したものです。構成の立て方、1枚あたりの情報量、締めのスライドの作り方など、個人が積み上げてきたノウハウを手順書として書き出します。それをClaudeに読み込ませれば、毎回ゼロから説明しなくても同じ品質の壁打ちを再現できます。

みのるんさんの事例が注目されたのは、個人の暗黙知だった資料作成フローを、誰でも試せる形で公開した点にあります。登壇経験が浅いエンジニアにとって、資料構成の型を学べる教材にもなります。

## Claude Skillsの仕組みをおさらいする

Claude Skills（クロード スキルズ）は、Claudeに繰り返し使わせたい手順や知識をファイルにまとめ、必要なときに呼び出せるようにする機能です。指示文だけでなく、参考テンプレートやチェックリストも一緒に読み込ませられます。

普段の会話でその都度説明していた前提知識を、スキルとして切り出しておく発想です。一度作れば、次からは呼び出すだけで同じ精度のやり取りができます。MCP（Model Context Protocol、外部ツールやデータ源とAIを接続する規格）が「外部ツールとの接続」を担うのに対し、Skillsは「Claude自身の振る舞い方」を定義するイメージに近いです。

## みのるん式ノウハウが注目されている理由

登壇資料作りは、内容そのものよりも構成の組み立て方で品質が大きく変わります。伝えたいメッセージを1つに絞る、聞き手の前提知識を想定する、結論を先に置く。こうした型は経験者ほど自然にできてしまい、言語化されにくいものです。

みのるんさんの公開が反響を呼んだのは、この言語化されにくい部分をスキルという再利用可能な形に落とし込んだからだと考えられます。読んだだけでは真似しにくいノウハウを、AIとの対話に組み込める状態にしたわけです。資料作りに慣れていない人でも、同じ思考プロセスをなぞれるようになります。

## 実際にClaude Skillsで資料作りを試した所感

今回、筆者も手元で簡単なスキルファイルを1つ作り、資料構成の壁打ちに使ってみました。あらかじめ「結論→根拠→具体例の順で聞く」という自分の癖をスキルに書いておくと、毎回同じ切り口で質問を投げ返してくれる感触があります。口頭で説明し直す手間が減るのは、率直に助かりました。

一方で、みのるんさんが公開している登壇資料スキルの具体的な項目立てまでは、本記事では検証していません。中身の詳細を確認したい場合は、公開元の記事を直接あたることをおすすめします。

## 登壇資料スキルを自分で作る手順

自分の登壇資料ノウハウをスキル化する手順は、次の4ステップで進められます。

### 手順1: 自分の資料作りの型を書き出す

構成の順番、スライド1枚に入れる情報量、避けている表現などを箇条書きにします。感覚でやっていることほど、言葉にする価値があります。

### 手順2: SKILL.mdとしてまとめる

書き出した型を、Claude Skillsが読み込める形式のファイルにします。最小構成は次の通りです。

```markdown
---
name: presentation-outline
description: 登壇資料の構成案を作るときに使うスキル
---

# 登壇資料構成のルール

1. 伝えたいメッセージを1つに絞る
2. 結論を先に置き、根拠と具体例を後に続ける
3. 1スライド1トピックを守る
4. 最後のスライドで次のアクションを示す
```

### 手順3: Claudeに読み込ませて壁打ちする

実際の登壇テーマを渡し、このスキルを使って構成案を作らせます。出てきた案が自分の型からずれていないか確認します。

### 手順4: 使うたびに修正して育てる

使ってみて違和感があった部分は、スキルファイルに追記します。1回で完成させず、資料を作るたびに更新するのが現実的です。

## デメリット・向いていない人

登壇資料スキルには向き不向きがあります。

まず、資料作りの型がまだ固まっていない人には向きません。書き出すノウハウ自体が少ないと、スキルの中身も薄くなってしまいます。

次に、案件ごとに聞き手の前提知識が大きく異なる仕事をしている人にも注意が必要です。汎用的な型を作っても毎回微調整が必要になり、スキル化のメリットが薄れます。

また、Claude Skillsの設定や運用に時間を割きたくない人にも向きません。スキルファイルは作って終わりではなく、使うたびに見直す前提のツールです。この手間を惜しむと、かえって非効率になります。

## 残る問い

登壇資料作成スキルは、個人の経験を再利用可能な資産に変える試みとして興味深い動きです。次に試すべきは、自分の資料作りの癖を実際に書き出してみることです。言語化した時点で、それが本当にスキル化する価値のある型かどうかが見えてきます。

## よくある質問

### Claude Skillsとは何ですか

Claudeに繰り返し使わせたい指示やテンプレートをファイルにまとめ、必要なときに呼び出せるようにする機能です。会話のたびに前提を説明し直す手間を減らせます。

### 登壇資料作成スキルは誰が公開していますか

みのるんさんが自身の登壇資料の作り方をスキルとして公開しています。詳細は本人の記事（https://qiita.com/minorun365/items/ed4c760f616cf3c0a958 ）で確認できます。

### Claude SkillsとMCPは何が違いますか

MCP（Model Context Protocol）は外部ツールやデータ源とAIをつなぐ規格です。Skillsは外部接続ではなく、Claude自身の振る舞い方や手順を定義する仕組みという違いがあります。

### 登壇資料作成スキルを使えば誰でも良い資料が作れますか

スキルは型を再現する助けにはなりますが、伝えたい内容そのものを考えるのは作成者自身です。中身が薄いままスキルだけに頼っても、質の高い資料にはなりません。

### 自分の資料作りをスキル化するのは難しいですか

最初の一歩は、自分がいつも意識している構成の順番を書き出すだけで始められます。完璧な型を最初から作る必要はなく、使いながら育てる前提で問題ありません。

### スキルファイルはどこに保存すればいいですか

Claude Skillsが読み込める場所にSKILL.mdなどのファイルを置いて管理します。具体的な配置方法は、利用しているClaudeの環境のドキュメントに沿って確認してください。

### 登壇資料以外にもスキル化できますか

構成に型がある作業であれば応用できます。議事録のまとめ方やレビューの観点など、繰り返し使う思考の手順は同じ発想でスキル化できます。
