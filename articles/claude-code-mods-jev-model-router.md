# Claude Code ModsとJevで作るモデルルーター入門

## この記事の要点

- Claude Code Mods は、Claude Code 内で動く関数フック形式のプラグインで、セッション中にホットリロードできる拡張の仕組みです。
- モデルルーターとは、依頼の難しさに応じて Opus・Sonnet・Haiku などのモデルを使い分ける仕組みです。Mods と Jev を組み合わせた実装例が Qiita で紹介されています（https://qiita.com/moritalous/items/8b663db633dde3c49d62）。

## Claude Code Mods とは何か

Mods は、Claude Code の中に自作の表示や処理を差し込む仕組みです。私の環境で使えるスキル説明には、次のように書かれていました。

- ライブペイン、バンド、ステータスライン、トースト、フックを作れる
- 関数フックを集めたプラグインとして書く
- 動いているセッションにホットリロードされる

この説明は、実際に自分の環境に表示されていた記述です。ターミナルでもデスクトップアプリの Code タブでも使える、とも書かれていました。

つまり Mods は、Claude Code の外から眺めるツールではありません。本体の動きに「フック」で割り込める拡張点です。

### フックでできることの見取り図

フックとは、特定のタイミングで呼ばれる関数のことです。たとえば次のような用途が考えられます。

- 依頼の送信前に内容を見る
- 応答の後でログを残す
- ステータスラインに状態を出す

モデルルーターは、このうち「依頼を見て、使うモデルを決める」役割にあたります。ただし、フックでモデル切り替えまで直接できるのかは、私は確認できていません。ここは TBD です。

## モデルルーターとは何か

モデルルーターは、道案内の交通整理のようなものです。簡単な依頼は軽いモデルへ、難しい依頼は強いモデルへ振り分けます。

### なぜ使い分けたいのか

理由は主に3つあります。

- 軽い作業に最上位モデルを使うのは、枠のもったいない使い方になりやすい
- 軽いモデルのほうが、一般に応答が速い
- サブスクの利用上限を、長く持たせたい

サブスクでは、使った量が上限に近づくと制限がかかります。重い作業と軽い作業を分けるだけで、体感はかなり変わるはずです。ただし、削減量の数値は私が測っていないので書きません。

### 現行モデルの役割分担の例

Anthropic のモデル ID は次のとおりです（環境で提示された情報です）。

| モデル | ID | 向いていそうな役割 |
|---|---|---|
| Opus 5.5 | `claude-opus-5-5` | 設計・難しいデバッグ |
| Sonnet 5.5 | `claude-sonnet-5-5` | 日常の実装・レビュー |
| Haiku 4.5 | `claude-haiku-4-5-20251001` | 要約・整形・単純な検索 |

「向いていそうな役割」は私の設計案です。公式の推奨ではありません。

## 設計の型：ルーターを自作するなら

Jev の実装に依存しない、考え方の型を書きます。以下は概念を示す擬似コードで、実在の API ではありません。

```js
// 概念例: 依頼の特徴からモデルを選ぶ
function pickModel(prompt) {
  if (/設計|アーキテクチャ|原因が分からない/.test(prompt)) return "opus";
  if (prompt.length < 200 && /要約|整形|翻訳/.test(prompt)) return "haiku";
  return "sonnet"; // 迷ったら中間
}
```

### ルールを決めるときの3原則

- **既定値は中間モデルにする。** 判定に失敗しても、被害が小さいためです。
- **手動で上書きできるようにする。** 自動判定は必ず外れます。
- **選んだモデルを画面に出す。** ステータスラインに出せば、挙動を疑いやすくなります。

ここで Mods のステータスライン機能が活きそうです。ルーターの判断を可視化できるからです。

### 判定方法の比較

| 方式 | 精度 | 手間 | 注意点 |
|---|---|---|---|
| キーワード一致 | 低〜中 | 小 | 取りこぼしが多い |
| 文字数・ファイル数 | 低 | 小 | 難しさとは別物 |
| 軽いモデルに分類させる | 中〜高 | 中 | 分類自体に枠を使う |

最初はキーワード一致で十分です。足りなくなってから分類モデルを検討する順が現実的でしょう。

## サブスクで使えるのは本当か

結論から言うと、「そう紹介されている」としか私には言えません。根拠は題材の見出しと Qiita 記事の存在だけです。

確認すべき点は次のとおりです。

- 利用しているプランの利用規約で、この接続方法が許されるか
- 第三者ツールを経由した利用が、規約上どう扱われるか
- 上限に達したときの挙動

規約違反でアカウントに影響が出ては本末転倒です。導入前に Anthropic の公式ドキュメントとプランの規約を読んでください。

## デメリット・向いていない人・うまくいかないケース

ルーターは万能ではありません。次のケースでは、むしろ逆効果になりえます。

### 向いていない人

- 作業の大半が難しい設計やデバッグの人。ほぼ最上位モデルに振られるので、ルーターの恩恵が薄いです。
- 設定をいじる時間がもったいない人。調整自体が作業になります。
- 規約確認に時間をかけたくない人。サブスク流用の構成は特に慎重さが要ります。

### うまくいかないケース

- **誤判定:** 難しい依頼が軽いモデルに回ると、やり直しで逆に枠を消費します。
- **文脈の断絶:** セッション途中でモデルが変わると、挙動の癖が変わって混乱することがあります。
- **仕様変更:** Mods は新しい仕組みです。Jev のような周辺ツールを含め、更新で動かなくなる可能性があります。

### 小さく試すなら

いきなり自動切り替えにしないでください。まず「今どのモデルを使うべきか」を提案するだけの表示から始めるのが安全です。提案が当たる割合を数日見てから、自動化に進みます。

## よくある質問

### Claude Code Mods とは何ですか？

Claude Code 内にペインやステータスライン、フックを追加できるプラグイン機構です。関数フックとして書き、動作中のセッションにホットリロードされると説明されています。

### モデルルーターとは何ですか？

依頼の内容に応じて、使う AI モデルを自動で選ぶ仕組みです。簡単な作業は軽いモデル、難しい作業は強いモデルに振り分けます。

### Jev とは何ですか？

私は一次情報で確認できていないため、TBD です。Mods と組み合わせたモデルルーターの実装例が、Qiita で紹介されています（https://qiita.com/moritalous/items/8b663db633dde3c49d62）。

### サブスクのまま API 課金なしで使えますか？

紹介記事ではそのように扱われているようですが、私は規約面を確認できていません。導入前に、利用中プランの規約と Anthropic の公式情報を確認してください。

### モデルルーターで利用枠は節約できますか？

軽い作業を軽いモデルに回せれば、節約につながる可能性があります。ただし誤判定でやり直しが増えると逆効果で、削減量の数値は私が測っていません。

### どのモデルをどの作業に割り当てればよいですか？

設計と難しいデバッグは Opus、日常の実装は Sonnet、要約や整形は Haiku という分担が出発点になります。これは私の設計案で、公式の推奨ではありません。

### 最初に試すなら何から始めるべきですか？

自動切り替えの前に、推奨モデルを表示するだけの構成から始めてください。提案の的中率を数日見てから、自動化を判断するのが安全です。
