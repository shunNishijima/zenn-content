## Claudeのスキルとは何か

スキル（Skills）は、Claude に特定の作業手順を覚えさせる仕組みです。基本は `SKILL.md` というファイルに、説明と手順を書きます。公式ドキュメントはこちらです。

- Claude Code のスキル: https://docs.claude.com/en/docs/claude-code/skills

説明文（description）を手がかりに、Claude が必要な場面で読み込む設計のようです。つまり推敲スキルとは、「推敲するときの観点と手順」を毎回貼らずに済ませる道具です。

## 日本語推敲スキルの3タイプ

個別のスキル名を並べる前に、型で整理します。名前が変わっても、型は使えるからです。

| タイプ | 中身 | 強み | 弱み |
|---|---|---|---|
| ルール列挙型 | 禁止表現・文長・接続詞などを箇条書きで指示 | 結果が読みやすく、修正理由も追える | ルールが多いと不自然な文になりやすい |
| 校正ツール連携型 | textlint など既存の校正ツールを呼び、結果を Claude が整理 | 機械的な誤りを再現性高く拾える | 文のわかりやすさまでは直せない |
| 文体・人格指定型 | 「編集者として」など役割と文体を指定 | 全体のリズムが整いやすい | 毎回ぶれる。理由が不透明になりがち |

yomiyasu がどの型に近いかは、元記事や公開リポジトリで確認してください。私はまだ確認できていません。

## 自分の原稿で比べる手順

評判より、手元の原稿での差分が確実です。次の手順をおすすめします。

### 1. 比較用の原稿を3本用意する

次のような種類を1本ずつ選びます。

- 技術ブログ（コードや専門用語が多い）
- 社内ドキュメント（敬体と常体が混ざる）
- 長めの説明文（1文が長くなりがち）

### 2. 条件をそろえる

同じモデル、同じ原稿、同じ指示で実行します。「推敲して」とだけ書き、スキルの差を見ます。

### 3. 差分を見る

出力を丸ごと読むと疲れます。差分表示で確認しましょう。

```bash
diff -u original.md skill_a.md
diff -u original.md skill_b.md
```

### 4. 採点軸を決める

次の観点を、あらかじめ決めておくと迷いません。

- 意味が変わっていないか
- 事実や固有名詞を勝手に変えていないか
- 読みやすさが上がったか
- 自分の文体が残っているか
- 修正理由が説明されているか

一番大事なのは1つ目です。意味が変わる推敲は、読みやすくても失敗です。

## デメリット・向いていない人・うまくいかないケース

推敲スキルは万能ではありません。

**意味の改変リスクがあります。** LLM は、文をなめらかにするために内容を足し引きすることがあります。数値、バージョン、固有名詞は人が必ず確認してください。

**文体が均一になります。** 型どおりに直すと、書き手の味が薄まります。個人ブログで個性を残したい人には、ルール型を強く効かせる運用は合わないかもしれません。

**コード混じりの文章は崩れやすいです。** コードブロックやコマンドを、説明文として直してしまう事故があります。「コードは変更しない」と明示する必要があります。

**向いていない人もいます。** 原稿が数行で済む人は、スキルを入れるより、都度の指示のほうが軽いです。逆に、チームで文章基準を統一したい人には、スキルの共有が効きます。

私は今回、yomiyasu を自分で動かして検証していません。そのため、精度や使い心地の所感は書けません。ここまでは、公式ドキュメントの内容と一般的な運用上の注意に基づく整理です。

## 導入前のチェックリスト

どのスキルを入れる場合も、次を確認してください。

- 公開リポジトリのライセンスは何か
- `SKILL.md` に何が書かれているか（自分の原稿に不要な指示はないか）
- 外部コマンドを実行する記述がないか
- 更新が続いているか

スキルは、Claude に手順を渡すファイルです。他人が作ったものは、中身を読んでから入れるのが安全です。

## 次に取る行動

まず元記事を読み、3つのスキルがどの型に当たるかを自分の言葉で分類してください。そのうえで、手元の原稿1本を、2つのスキルに通してみましょう。

残る問いはひとつです。あなたの原稿にとって、「読みやすい」とは何を指すでしょうか。その答えが、スキル選びの基準になります。

## よくある質問

### yomiyasu とは何ですか？

Claude で日本語の文章を推敲するスキルとして話題になったものです。詳しい内容は、参考記事（https://qiita.com/inoyu-qiita/items/0ffe6e74ecaf3aaa8b14）で紹介されています。

### Claude のスキルとは何ですか？

特定の作業手順を `SKILL.md` などのファイルにまとめ、Claude に使わせる仕組みです。仕様は公式ドキュメント（https://docs.claude.com/en/docs/claude-code/skills）で確認できます。

### 日本語推敲スキルはどれを選べばよいですか？

用途で選びます。誤字や表記ゆれを確実に拾いたいなら校正ツール連携型、読みやすさ全体を整えたいならルール列挙型や文体指定型が候補です。

### 推敲スキルを使うと文章の意味が変わることはありますか？

あります。LLM は文をなめらかにする過程で、内容を足したり削ったりすることがあります。数値や固有名詞は、人が差分で確認してください。

### 複数のスキルを公平に比較するにはどうすればよいですか？

同じモデル、同じ原稿、同じ指示で実行し、差分を見ます。意味の保持、事実の保持、読みやすさ、文体の残り方といった採点軸を、先に決めておくと比較しやすくなります。

### 他人が作ったスキルを入れても安全ですか？

中身を読んでから入れるのが安全です。外部コマンドの実行や、不要な指示が含まれていないかを確認してください。

### 推敲スキルは個人ブログにも向いていますか？

向く場合もありますが、文体が均一になる点に注意が必要です。個性を残したいなら、直す範囲を絞る指示を加えるとよいでしょう。
