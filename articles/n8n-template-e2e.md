## TL;DR

- n8n の有料テンプレート（楽天カード明細CSVからサブスクを自動検出するワークフロー）を出荷する直前に、Docker の実 n8n で通し検証をやった
- 検出ロジックの単体テストは vitest 29件すべて緑。それでも実環境では **2箇所で確実に壊れる**状態だった
- 原因はどちらもロジックではなく、**現行 n8n のセキュリティ既定値**。「テスト全緑」と「実環境で動く」は別物だった

## 作っていたもの

楽天カードの明細CSVを n8n に読み込ませると、「別々の月に2回以上・ほぼ同額」の課金をサブスクとして検出し、年額換算と解約ページURL付きで一覧化するワークフロー。検出ロジックは JavaScript の純関数群（名寄せ・ノイズ除外・周期判定・年額換算）で、vitest のテスト29件と、n8n なしで通すスモークテストまで用意していた。

サンプルCSVを流すと Netflix / Spotify / Adobe の3件・年額合計 ¥37,120 が出る、という期待出力との一致もスモークで確認済み。ここまでやって「動作確認済み」のつもりだった。

## 出荷前に実環境E2Eをやったら

Docker の n8n 公式イメージ（最新版）にワークフローJSONをインポートして、購入者と同じ手順で実行した。結果、ロジックに到達する前に2回落ちた。

### 1. `access to env vars denied`

CSVのパスを `={{ $env.RAKUTEN_CSV_PATH }}` のように環境変数で渡す設計にしていた。これが現行の n8n では**式からの環境変数参照が既定で拒否**される。回避には `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` が要るが、購入者にそれを要求するのは筋が悪い。

→ 対処: 環境変数をやめ、ノードの File(s) Selector にパスを直接入力する方式に変更。

### 2. `Access to the file is not allowed`

環境変数を剥がしても、今度はファイル読み込みで拒否。現行 n8n は**読み込めるフォルダを明示的に許可する必要がある**（`N8N_RESTRICT_FILE_ACCESS_TO`）。

→ 対処: セットアップガイドの docker 起動例にマウントと許可設定を明記し、エラーメッセージ別のFAQも追加。

```bash
docker run -it --rm -p 5678:5678 \
  -v ~/rakuten-csv:/data \
  -e N8N_RESTRICT_FILE_ACCESS_TO=/data \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n
```

## 修正後の再検証

ガイドの docker コマンドそのままの条件で、インポート → Code ノードにスニペット貼り付け → 実行、が完走。3件・¥37,120 が期待出力と完全一致した。ついでに、許可設定を外すとFAQに書いたエラーがそのまま再現することも確認できた（トラブルシューティングの裏取り）。

## 学び

1. **単体テストは「ロジックが正しい」ことしか保証しない**。実環境の権限・設定・バージョン差は別のレイヤで壊れる
2. n8n は近年セキュリティ既定値が強化されており、**古めのテンプレ設計（$env 参照・任意パス読み込み）はそのままでは動かない**
3. 有料で配るものは、**購入者と同じ手順を最低1回実環境で通す**。今回は30分の検証で返金・低評価リスクを2件潰せた
